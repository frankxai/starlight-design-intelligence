# Portfolio experience standard

Use the best reference work to improve a user's task, then express that mechanism
through the relevant brand. This standard connects the existing observatory,
brand packs, product registry and tool policy. It creates no second authority.

The [machine-readable standard](experience-standard.json) covers **11 brand/domain
profiles, 13 owning repositories and 14 registered surfaces**, with eight common
acceptance checks and 15 bounded upgrades. Jobs and actions are proposed design
requirements. Dated observations establish their stated scope only. Nothing here
proves that a production journey passes.

## Reference learning

Six **primary-page text** reviews were made on 30 September 2026. These do not
refresh the observatory's earlier browser snapshot dates or establish current
rendered, responsive, accessibility or motion quality. Recheck a source before a
new redesign; capture actual desktop, phone and interactions when layout or motion
is the proposed influence. League Universe was excluded from this refresh because
retrieval was insufficient, not because a broken route was established.

Transfer abstract mechanisms only. Third-party marks, assets, fonts, code,
components and distinctive compositions remain reference-only. Public Git stores
normalized observations and explicit inferences. Raw source captures stay private.

## Shared experience acceptance

1. **Task:** one recipient, job and bounded action leads to a usable outcome.
   Record completion, time, errors and user observations. Establish a baseline
   before promising improvement; different journeys need different targets.
2. **Proof:** each consequential claim has adjacent source, date, status, rights
   and limitations. A logo wall or repository name cannot replace evidence.
3. **States:** loading, empty, error, success, disabled and unavailable states are
   designed where applicable. Failed actions preserve inputs and explain recovery.
4. **Accessibility:** test the complete keyboard journey, visible focus, semantics,
   contrast, 1440/390/320px layouts, 200% zoom and long real content.
5. **Typography:** sentence case, real lowercase, approved roles, licensed weights,
   intentional fallback and inspected exports. Preserve proper names and acronyms.
6. **Motion:** a named job, responsive control, complete static journey and designed
   reduced-motion equivalent. Measure actual loading, layout and input behavior.
7. **Portability:** save, reopen, share and download work where promised; inspect
   the actual export, including text, fonts, crops, links, rights and factual copy.
8. **Release:** retain the existing gates, independent verification and named owner
   approval. Capture the preview, then scoped production proof and exact rollback.

The existing web-release validator remains the release authority. Existing bars
remain editorial **18/20**, typography **15/16**, visual **28/30**, and shipped
motion **16/18** or a documented cut. Structural validation of this standard
cannot award those scores or prove taste, accessibility or user satisfaction.

## Bring GitHub sources into the tools

Run the checks and create a read-only bundle from an immutable commit:

```bash
npm run validate:experience
npm run export:brand -- --brand frankx --out /tmp/frankx-handoff
# Optional: --revision <full-40-character-commit-sha>
```

The exporter packages committed brand documents, the exact runtime pack, domain
profiles, existing gates and a filtered adapter plan. Its manifest hashes the
source bytes and identifies the kernel revision. Working edits cannot leak into
an apparently pinned bundle. It refuses to overwrite an existing directory.
It exports no font/media binaries and performs no remote writes.

| Destination | Use the bundle for | Evidence before publishing |
| --- | --- | --- |
| Product repository | Reconcile the pinned pack with local tokens, semantic roles, components and recorded decisions | Existing adoption validator plus a real flow and release evidence |
| Figma | Generate product-owned aliases/text styles; review a desktop and phone flow; add the first needed component family | Projection provenance, real states, code-prop mapping and visual comparison |
| Canva | Build one approved kit and two locked content templates, preserving source/date and rights fields | Actual font substitution, crop, factual-copy and export inspection; separate fillable-field proof |
| Docs, slides, social, video | Apply the same approved roles and claims to the intended viewing context | Inspect the exported artifact, phone/readability behavior and usage rights |
| Media delivery | Register approved derivatives and their live uses in the selected DAM | Existing rights, approval, transformation, delivery and usage proof |

Do not infer a complete semantic token API from the runtime pack's small palette.
Do not publish vendor reference kits as owned components. An equivalent explicit
code-prop mapping can be piloted while Code Connect eligibility remains unresolved;
a plan change or purchase is a separate decision.

## Execution order and honest limits

Start with source reconciliation and content truth. Then prove the FrankX Figma
flow and a single-brand Canva template pilot. Move each owning product through its
queued journey upgrade, one bounded task at a time. Capture before/after evidence
and test the full outcome rather than expanding a component matrix first.

The dated audit found foundations but no local components on inspected FrankX
pages; inspected Arcanea/GenCreator files lacked owned system content. Figma's
account tool quota blocked further inspection. Canva inventory and folder counts
do not prove kit approval, template automation or export quality. Private names,
IDs, draft strategy and raw evidence remain outside public Git.

Closing a queue item requires its stated exit evidence in the owning repository
or private tool receipt. The queue deliberately has no `adopted`, `approved` or
`released` status: use the existing owner decision and release contracts instead.
